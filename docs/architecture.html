플레이어가 마을의 여러 NPC에게 말을 걸면, 각 NPC가 자신의 성격·지식에 맞춰 한국어로 대답하고 그 대사를 음성으로 재생한다. 대화 생성(LLM)과 음성 합성(TTS) 모두 로컬에서 구동 — 외부 API·인터넷 없이 동작하는 오프라인 AI 파이프라인.

System Architecture

하나의 프록시로 게임과 AI를 분리

게임(UE)은 “어디로 요청할지”만 알면 된다. 채팅·음성·(향후)음성인식을 모두 파이썬 프록시 한 곳에 모아, UE 코드를 거의 건드리지 않고 기능을 계속 붙일 수 있게 설계했다.

Data Flow

두 개의 독립 파이프라인

대사(텍스트)는 즉시 화면에 뜨고, 음성은 준비되는 대로 재생된다 — 서로를 막지 않는다. 음성 합성이 실패해도 대화는 끊기지 않는다.

Text · 대화

플레이어 질문 → NPC 대사

  1. E키로 대화 시작 → 초기 인사 표시, 입력 잠금.
  2. 시스템 프롬프트(성격·지식·금지) + 최근 기록 + 메시지를 OpenAI 형식으로 조립.
  3. 프록시가 llama-server로 그대로 중계 → 대사 생성.
  4. 현재 NPC의 응답만 필터링해 UI에 표시.
Voice · 음성

NPC 대사 → 한국어 음성

  1. 대사가 확정되면 그 텍스트를 /tts로 전송.
  2. MeloTTS가 한국어 음성(WAV)을 합성해 반환.
  3. UE가 WAV 헤더를 파싱(FWaveModInfo)해 PCM 추출.
  4. USoundWaveProcedural로 NPC 위치에서 3D 재생. 실패는 조용히 무시.
Characters

Engineering Log

한국어 TTS를 Windows에 올리기까지

“한국어 되는 로컬 TTS”를 붙이는 과정에서 실제로 뚫은 벽들. 계약(입출력 규격)을 먼저 고정해, 엔진을 나중에 바꿔도 UE 코드는 그대로 쓰도록 설계했다.

01

엔진 오선택 정정

처음 고른 Kokoro-82M이 공식적으로 한국어 미지원임을 발견 → 한국어를 정식 지원하는 MeloTTS(MIT, CPU 실시간)로 교체.

02

Python 3.12 설치 실패

MeloTTS의 구버전 의존성(tokenizers·fugashi)이 3.12용 wheel이 없어 소스 빌드에 실패 → Python 3.11로 전환해 해결.

03

의존성 충돌 3종

librosa의 pkg_resources 누락은 setuptools<80으로 복원. 한국어 G2P가 요구하는 eunjeon은 Windows 빌드 실패, 대체재 python-mecab-ko는 mecab-python3와 대소문자 폴더 충돌.

04

kiwipiepy 어댑터로 우회

wheel이 깔끔한 kiwipiepy(형태소 분석기)를 eunjeon.Mecab 인터페이스로 감싸는 얇은 어댑터를 만들어 주입 → 한국어 발음 규칙 처리를 복원.

05

계약 기반 통합 검증

POST /tts → 200 · audio/wav (mono·16bit·44.1kHz) · CPU 실시간(~1×) 한국어 합성 확인. UE는 이 WAV 계약만 알면 되므로 엔진 교체에 영향받지 않는다.
