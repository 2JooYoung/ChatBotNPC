# ChattingNPC 노션 포트폴리오 디자인

## 목적

신입 개발자 지원용으로 ChattingNPC 프로젝트 하나를 짧게 소개한다. 코드 설명보다 문제의식(WHY), 설계 판단, 동작 흐름(HOW), 문제 해결과 검증 결과를 중심으로 작성한다.

## 결과물

- 노션에 그대로 복사할 수 있는 Markdown 문서 1개
- 본문에 삽입할 기존 스크린샷 3장
  - 게임 내 NPC 대화 화면
  - LLM·TTS 서버 실행 로그
  - NPC별 음성 설정 화면
- UE, FastAPI 프록시, LLM, TTS의 관계를 보여주는 구조도 이미지 1장
- 별도의 웹 레이아웃이나 PDF 디자인은 만들지 않는다.

## 독자와 분량

- 독자: 신입 개발자 채용 담당자와 실무 개발자
- 범위: ChattingNPC 단일 프로젝트
- 분량: 노션의 짧은 프로젝트 케이스 스터디 1편
- 문체: 짧고 단정한 한국어. 기능을 나열하기보다 선택 이유와 결과를 먼저 설명한다.

## 문서 구성

1. **표지**
   - 프로젝트 한 줄 소개
   - 게임 대화 화면
   - Unreal Engine 5.7, C++, Local LLM, FastAPI, MeloTTS
2. **WHY**
   - 정해진 대사를 반복하는 기존 NPC의 한계
   - 비용, 인터넷 의존, 데이터 외부 전송 없이 대화형 NPC를 만들려는 목표
3. **설계 목표**
   - 완전 오프라인
   - 외부 API 호출과 호출당 비용 없음
   - NPC별 성격과 대화 기록 분리
   - 채팅과 음성 장애 격리
4. **전체 구조**
   - UE는 FastAPI 프록시 주소 하나만 인식
   - 프록시 뒤에서 llama-server와 MeloTTS가 독립 동작
   - 서버를 분리한 이유는 교체 가능성, 관심사 분리, 장애 격리
5. **HOW: 대화**
   - NPC 프로필, 최근 대화, 사용자 입력 조립
   - 프록시를 통한 로컬 LLM 요청
   - 응답 검증 후 UI 표시
6. **HOW: 음성**
   - 확정된 NPC 대사를 `/tts`로 전달
   - 한국어 WAV 합성
   - UE에서 NPC 위치의 3D 음성으로 재생
7. **문제 해결과 결과**
   - 늦은 응답 폐기와 객체 유효성 확인
   - TTS 실패가 텍스트 대화를 막지 않도록 분리
   - Windows에서 한국어 TTS 의존성 충돌 해결
   - NPC 3명, 외부 API 0, 오프라인 동작 결과
   - 배운 점과 다음 개선 방향

## 핵심 설계 설명

### 구성 요소

- **Unreal Engine:** 상호작용, 대화 UI, NPC별 세션, HTTP 요청, 음성 재생
- **FastAPI 프록시:** 채팅 중계와 TTS를 한 주소로 제공
- **llama-server:** 로컬 LLM을 실행해 NPC 대사 생성
- **MeloTTS:** 한국어 대사를 WAV 음성으로 합성

### 데이터 흐름

- 텍스트: 플레이어 입력 → UE 요청 조립 → FastAPI → llama-server → FastAPI → UE 대화창
- 음성: NPC 대사 확정 → UE → FastAPI `/tts` → MeloTTS → WAV → UE 3D 재생
- 텍스트와 음성은 별도 요청으로 처리해 음성이 실패해도 대화를 유지한다.

### 오류 처리

- 비동기 콜백에서 객체 유효성을 확인한다.
- 요청 ID로 오래되거나 다른 NPC의 응답을 폐기한다.
- TTS 로드·합성 실패는 음성 기능에만 영향을 주고 채팅 중계는 계속 동작한다.

### 검증 근거

- Unreal Editor PIE에서 NPC 접근, 대화, 입력 복구, NPC별 기록 분리를 확인했다.
- MVP 체크리스트 16개 항목을 통과했다.
- `/tts`가 한국어 16-bit PCM WAV를 반환하고 UE에서 재생되는 것을 확인했다.
- 서버가 꺼진 경우에도 크래시 없이 오류를 처리하도록 검증했다.
